# 15 — API Specifications

REST + webhooks, OpenAPI 3.1. The full machine-readable spec is generated by FastAPI at
`/openapi.json` and a curated source-of-truth lives at `services/openapi/condominioos.yaml`.
All APIs are **versioned** (`/v1`), **tenant-scoped**, **authenticated** (OIDC bearer / service mTLS),
and **rate-limited**.

---

## Conventions
- Base: `https://api.condominioos.eu/v1`
- Auth: `Authorization: Bearer <jwt>`; tenant from token claim or `X-Condominium-Id` (validated).
- Idempotency: `Idempotency-Key` header on POST/PUT.
- Errors: RFC 9457 Problem Details (`application/problem+json`).
- Pagination: cursor (`?cursor=&limit=`); responses include `next_cursor`.

## Resource APIs (selected)

### Registry
```
GET    /v1/condominiums/{id}
GET    /v1/condominiums/{id}/units
POST   /v1/condominiums/{id}/units
GET    /v1/units/{id}
GET    /v1/units/{id}/balance            # current charges/arrears
GET    /v1/owners/{id}  /v1/residents/{id}
```

### Documents
```

GET    /v1/documents?type=&q=
GET    /v1/documents/{id}
```

### Maintenance & Vendors

### Review (Ops Console / human-in-the-loop)

### Agent runtime (internal/ops)
```
POST   /v1/agents/runs                    # kick a task (mostly event-driven)
GET    /v1/agents/runs/{id}               # reproducibility: model, prompt_ver, tools, cost

POST   /v1/tenants/{id}/autonomy          # set tier policy (governed)

```

### Audit (read-only)
```
GET    /v1/audit/events?entity=&from=&to=
GET    /v1/audit/verify                   # hash-chain integrity check
```

## Webhooks (inbound from channels/providers)
```
POST   /v1/webhooks/whatsapp             # signature-verified → comms.message.received
POST   /v1/webhooks/email
POST   /v1/webhooks/pec
POST   /v1/webhooks/bank                  # payment notifications
```
All webhooks verify provider signatures, normalize via the Anti-Corruption Layer, and emit events;
they never trust payloads as instructions (prompt-injection defense, doc 06 §3).

## Example: submit an outbound draft to the firewall (internal contract)

`POST /internal/firewall/evaluate`
```jsonc
// request
{
  "tenant_id": "uuid",
  "artifact": {
    "kind": "message",                  // message | reminder | convocation | financial_action | vendor_message
    "channel": "whatsapp",
    "recipient": {"type": "resident", "id": "uuid", "unit_id": "uuid"},
    "text": "Gentile Sig. Rossi, ...",
    "citations": [{"doc_id":"uuid","span":"art. 1130"}],
    "claims": [{"text":"la prossima assemblea è il 20/06","source":"assembly:uuid"}],
    "financials": null
  },
  "agent": "concierge",
  "confidence": 0.9
}
// response
{
  "verdict": "APPROVE",                  // APPROVE | REVISE | HOLD | BLOCK
  "verdict_id": "uuid",
  "artifact_hash": "sha256:...",
  "signature": "...",                    // notification engine verifies this
  "layer_scores": {"L1":1,"L2":0.95,"L3":1,"L4":null,"L5":1,"L6":0.9,"L7":"low","L8":"A3"},
  "autonomy_tier": "A3",
  "expires_at": "RFC3339",
  "revisions": []
}
```

The Notification Engine **rejects** any send request whose `verdict`≠`APPROVE`, whose `artifact_hash`
doesn't match the exact payload, or whose signature/expiry is invalid (doc 07 §8).
